# 本地互传 · Local File Express

局域网内打开网页即可互传文件的单页应用。文件通过 **WebRTC DataChannel 点对点直传**，服务器只负责在线注册、WebRTC 信令和局域网设备发现，**不转发、不缓存任何文件内容**。

- 单页应用，无构建步骤，`node server.js` 即用
- 在线客户端实时注册 / 广播
- 服务端扫描局域网机器（邻居表 + ARP + ICMP）
- 自定义 IP：真实 WebRTC 握手测试后保存到浏览器 `localStorage`
- 64KB 自适应分片、缓冲水位背压、增量 MD5 校验
- 无中继、无 HTTPS、不依赖外网 CDN

## 快速开始

```bash
npm install
npm start
```

终端会打印局域网地址：

```text
本机访问   http://localhost:3000
局域网     http://192.168.1.23:3000
```

在需要互传的设备上打开局域网地址即可。换端口：

```bash
PORT=8080 npm start
```

> 服务端绑定 `0.0.0.0:3000`，请只在可信任的局域网内运行。

## 使用流程

1. **在线客户端**：所有打开本页面的浏览器会自动注册，实时显示别名、IP、浏览器 / 系统。自己的卡片标“本机”。
2. **局域网设备**：服务端扫描所在网段，显示 IP、主机名、MAC、在线状态。
   - 已打开本页面的机器标“在线”，可直接发送。
   - 普通机器标“未打开页面”，可复制邀请链接发给对方。
3. **自定义设备**：
   - 输入在线浏览器的 IPv4 地址和备注名，点击“测试并添加”。
   - 会建立一次真实 WebRTC 连接并 ping/pong 三次，成功后保存到当前浏览器的 `localStorage`。
   - 支持编辑、删除、重新测试。IP 修改后状态会变成未验证。
4. **发送文件**：点击客户端卡片、局域网“发送”、自定义设备“发送”，或把文件拖到客户端卡片上。
5. **接收文件**：对方会收到确认弹窗；接受后逐文件校验 MD5 并触发浏览器下载。

## 传输设计

```text
浏览器 A ── WebRTC DataChannel（文件分片）── 浏览器 B
    │                                            │
    └────────── WebSocket 信令 ──────────────────┘
                     Node 服务端
            注册 / 在线列表 / LAN 扫描 / SDP/ICE
```

### 分片与背压

- 分片大小默认 **64KB**，按 `RTCPeerConnection.sctp.maxMessageSize` 自动下调，最低 16KB。
- `bufferedAmount` 高水位 **4MB**、低水位 **1MB**，用 `bufferedamountlow` 事件等待，不轮询。
- 文件读取预取 8 块（约 512KB），隐藏磁盘读延迟。
- 单条连接顺序传一个文件；控制消息为 JSON，文件块为原始二进制，不加每块头。
- 只在文件级 ACK，不做每块 ACK，避免 RTT 级停顿。

### MD5 校验

- 发送端边读边算 MD5，`file-end` 携带最终哈希。
- 接收端边收边算，收完比对 **MD5 + 字节数**。
- 校验通过才创建 Blob 并下载；失败则丢弃分片、不保存，并回报发送端。
- MD5 使用 `hash-wasm`（WASM）增量计算，资源已本地化。
- 与 LocalSend 默认“发送前先完整读一遍算哈希”不同，这里只读一遍，少一次全量磁盘扫描。

### 与 LocalSend 的取舍

LocalSend 由接收端启动 HTTP 服务，发送端用流式 POST 上传，接收端 `BufWriter` 合并写盘，并默认传 2 个文件。浏览器不能监听端口，因此这里把同一套流水线映射到 DataChannel：

| LocalSend | 本项目 |
| --- | --- |
| 512KB 读块 + 2MB 预读 | 64KB 分片 + 512KB 预读 |
| 有界队列 + 512KB 合并写 | `bufferedAmount` 高/低水位背压 |
| 2 个文件并行 | 单通道顺序传（SCTP 共享拥塞窗口，并行收益有限） |
| 发送前算 SHA-256 | 边发边算 MD5，只读一遍 |
| HTTP/1.1 避开 HTTP/2 流控 | DataChannel/SCTP，无 HTTP/2 流控问题 |

### 连接隔离

每次发送 / 测试建立一条独立的 `RTCPeerConnection`，用随机 `connId` 区分信令。这样同时双向发送时不会发生 SDP glare，也不需要共享连接状态。

## 为什么没有中继 / HTTPS

这是按需求刻意收敛的：

- **没有服务器中继**：WebRTC 建连失败就是失败，页面会提示原因，不会偷偷把文件传到服务器。
- **没有 HTTPS**：页面和 WebSocket 都是 `http://` / `ws://`。因此：
  - `showSaveFilePicker()` 等流式写盘 API 不可用（它们要求 secure context）。
  - 接收端只能在内存中累积分片，最后组 Blob 下载。
  - 单文件越大，内存压力越大，建议 **不超过 1GB**；超过会给出警告。
  - DataChannel 本身是 DTLS 加密的，文件内容不会明文经过网络。

## 已知限制

1. **只有打开了本页面的浏览器才能接收文件**。浏览器无法监听端口，普通局域网机器只能被发现；可以复制邀请链接让对方打开页面。
2. **局域网列表是服务端视角**。它扫描服务器所在网段；跨 VLAN、AP 隔离、防火墙、虚拟网卡会削弱结果。
3. **没有中继**：企业 Wi-Fi 的 AP 隔离、客户端隔离、禁用 mDNS 可能导致 WebRTC 直连失败。
4. **大文件保存受内存限制**：无 HTTPS 时无法流式写盘。建议分批发送。
5. **多文件下载可能被浏览器拦截**：请允许本站点“下载多个文件”；传输队列里也提供“再次保存”。
6. **iOS Safari**：后台标签页可能被挂起，传输时请保持前台。
7. 在线列表是实时内存状态，刷新页面会重新注册；自定义设备保存在 `localStorage`，刷新不丢。

## 故障排查

| 现象 | 检查 |
| --- | --- |
| 局域网列表为空 / 少机器 | 点击“完整扫描”；检查防火墙、AP 隔离、VPN；确认服务器和手机在同一网段 |
| 能看到设备但发送失败 | 检查是否阻止了 WebRTC；尝试关闭 VPN；确认两台机器能 mDNS 互访 |
| 输入 IP 提示没有页面 | 目标浏览器必须正在打开本页面；同一 IP 多个标签页时选择具体目标 |
| 接收端下载被拦截 | 浏览器地址栏允许“下载多个文件”；或在传输队列点“再次保存” |
| 大文件失败 | 无 HTTPS 下内存不足，改用更小的文件分批发送 |
| 端口被占用 | `PORT=8080 npm start` |

## 测试

```bash
npm test
```

覆盖邻居表解析、IPv4 校验、IP 排序、注册表与别名清洗。

手工端到端：

1. 两台设备（或两个浏览器）打开同一地址；
2. 互相出现在在线客户端；
3. 点击卡片发送一个几十 MB 的文件，接收端接受；
4. 双方传输队列显示进度、速度，文件状态出现 `MD5`；
5. 接收端下载的文件与源文件 MD5 一致。

## 安全说明

- 无认证、无 PIN。任何能访问该端口的局域网用户都可以注册并向他人发起文件请求。
- 接收默认需要手动确认，不会自动接收。
- 服务器不写入文件，也不保存传输内容。
- 请勿将端口暴露到公网。
